# 룬PT 운영 앱 정리 프롬프트 (트레이너 저장소용)

이 프롬프트는 `upvible/Rune-PT`를 열어 둔 Claude Code에 그대로 붙여 넣는다. 작업 대상은 운영 저장소이고, `chjisceo/rune-pt`는 읽기만 하는 참고 자료다.

두 단계로 나눈다. 1단계가 끝나 실제 사이트에서 확인되기 전에는 2단계를 시작하지 않는다. 단계마다 PR 하나다.

## 시작 전에

1. 운영 저장소를 git으로 받는다. GitHub 웹의 "Add files via upload"로 `index.html`을 통째로 올리지 않는다. 다른 수정이 소리 없이 덮인다.
2. 참고 저장소는 운영 저장소 밖에 받는다.
   ```sh
   git clone --branch feat/path-a-design https://github.com/chjisceo/rune-pt.git ../rune-pt-ref
   ```
   `../rune-pt-ref` 안의 파일은 고치지 않는다. 운영 저장소로 복사하는 것은 이 문서가 허용한 파일뿐이다.
3. 작업 전에 지금 사이트(`https://upvible.github.io/Rune-PT/`)에서 회원 로그인, 세트 저장, 선물함, 트레이너 회원 목록이 되는지 직접 확인하고 적어 둔다. 끝난 뒤 같은 항목을 다시 확인한다.

## 1단계: 한 파일을 여러 파일로 나누기 (동작 변경 없음)

`index.html`은 약 545KB다. 그중 스크립트가 약 519KB인데, 원래 따로 있던 파일들을 이어 붙인 것이다. 구분 주석이 그대로 남아 있다. 빌드 도구 없이 원래 파일로 되돌린다. GitHub Pages는 지금처럼 파일을 그대로 연다.

| 새 파일 | 옮길 부분 (`index.html`) |
|---|---|
| `css/app.css` | 첫 번째 `<style>` 안쪽 전부 |
| `js/rune-tier-core.js` | `/* ===== 티어 코어 (rune-tier-core.js) ===== */`부터 다음 구분 주석 바로 앞까지 |
| `js/rune-routine.js` | `/* ===== 루틴 엔진 (rune-routine.js) ===== */`부터 다음 구분 주석 바로 앞까지 |
| `js/catalog.js` | `/* ===== 종목 카탈로그 (catalog.js) ===== */`부터 다음 구분 주석 바로 앞까지 |
| `js/app.js` | `/* ===== 앱 ===== */`부터 첫 `</script>` 바로 앞까지 |

규칙:

- 글자를 바꾸지 않는다. 잘라서 옮기기만 한다. 포매터, 들여쓰기 정리, 변수 이름 변경, 세미콜론 정리를 하지 않는다. 옮긴 뒤 새 파일들을 순서대로 이어 붙이면 원래 스크립트와 바이트 단위로 같아야 한다. 이것을 명령으로 확인하고 결과를 PR에 적는다.
- `<script type="module">`을 쓰지 않는다. 일반 `<script src>`로, 위 표의 순서대로 `</body>` 앞에 둔다. `app.js`는 최상위 `const`와 `function`을 전역으로 공유하므로 이 단계에서는 더 쪼개지 않는다.
- `<head>`의 테마 선적용 스크립트, supabase-js CDN 태그, 서비스워커 등록 스크립트는 지금 자리에 둔다.
- `SB_URL`, `SB_KEY`, `APP_URL` 값은 옮겨진 파일 안에 그대로 있을 뿐이다. 값을 PR 본문, 커밋 메시지, 로그에 적지 않는다. `sb_secret`, `service_role`은 어디에도 넣지 않는다.

서비스워커와 빠진 파일:

- 지금 `sw.js`의 `SHELL`에는 `manifest.webmanifest`, `icon-192.png`, `icon-512.png`가 있지만 저장소와 사이트에는 없다(404). `cache.addAll`은 하나라도 없으면 실패하므로, 지금은 서비스워커 설치와 오프라인 화면이 동작하지 않는다. `index.html`의 `apple-touch-icon.png`도 없다.
- 이 단계에서 `SHELL`은 실제로 있는 파일만 적는다. `./`, `index.html`, `css/app.css`, `js/*.js` 네 개다. 버전 `V`를 `rpt-v3`로 올린다. fetch와 push 핸들러는 고치지 않는다.
- 아이콘과 매니페스트를 새로 만들지는 사용자(트레이너)에게 묻는다. 만들지 않으면 `<head>`의 해당 `<link>`는 그대로 둔다.

1단계 끝난 기준:

- `index.html`은 HTML 껍데기와 링크만 남아 수십 KB 이하다.
- 브라우저 콘솔에 새 오류가 없다. 회원 로그인, 세트 저장, 동기화 표시, 선물함, 트레이너 회원 목록·달력·기록 피드가 시작 전과 같다.
- 기존 `localStorage`의 `rpt1`을 가진 브라우저에서 열어도 기록이 그대로다.

## 2단계: 새 화면 입히기

1단계가 배포되고 위 기준을 확인한 뒤에 시작한다.

`../rune-pt-ref/design-review/병합-프롬프트.md`를 따른다. 그 문서는 단일 `index.html`을 전제로 썼으므로 아래처럼 바꿔 읽는다.

- "`index.html`의 다섯 군데"는 탭 라벨, 회원 기본 탭, `viewHome()` 문구를 뜻한다. 이 세 곳은 이제 `js/app.js`에 있다. 스타일·스크립트 링크 두 줄만 `index.html`에 추가한다.
- 새 파일 `ui/path-a.css`, `ui/path-a.js`, `ui/muscle.js`는 `js/app.js` 뒤에 로드한다. `sw.js`의 `SHELL`에 추가하고 `V`를 한 번 더 올린다. 병합 프롬프트의 "`V`를 올리지 않는다"는 이 문서가 대신한다.
- 시각 기준 이미지는 `../rune-pt-ref/design-review/proposed/`의 여섯 장이다. 저장소로 복사하지 않고 보기만 한다.
- 3D 근육 모형 `stayfit-muscle-skeleton.glb`(약 4.97MB)는 참고 저장소에 들어 있지 않다. Harry에게 따로 받는다. 받기 전에는 포스터와 부위 이름만 있는 다이얼로그로 끝낸다. Draco 디코더 `../rune-pt-ref/apps/web/public/draco/` 세 파일은 그대로 `draco/`로 복사해도 된다.

가져오지 않는 것:

- `apps/web`, `packages/core`의 React·TypeScript 코드, `package.json`, Vite·Tailwind 설정. 운영 앱에 빌드 단계를 만들지 않는다.
- `packages/core/src/tierCore.ts`. 운영의 `RuneTier`가 더 많은 규칙(나이·성별 계수, 풀업, 달리기, 승급 퀘스트, 트레이너 인장)을 갖고 있다.
- `sampleData.ts`의 샘플 회원·운동·선물, 체험(데모) 로그인 버튼, "예시"라는 말.
- `localRuneRepository.ts`. `rpt1`을 다른 모양으로 쓴다.

## 작업 방식

- 단계마다 브랜치를 따고 PR을 연다. `main`에 바로 올리지 않는다.
- PR 본문에 무엇을 옮겼는지, 확인한 항목, 확인하지 못한 항목을 나눠 적는다.
- 기존 계산 함수(`RuneTier`, `RuneRoutine`, `recommend`, `plan`, `syPull`, `syMerge`, `syFlush`, `srvSave` 등)는 호출만 하고 다시 구현하지 않는다.
- 막히면 동작을 줄이는 쪽이 아니라 그 화면의 변경을 빼는 쪽을 고르고, 사용자에게 알린다.
