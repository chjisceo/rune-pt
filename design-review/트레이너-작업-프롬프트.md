# 룬PT 새 화면 반영 프롬프트 (트레이너 저장소용)

이 프롬프트는 `upvible/Rune-PT`를 작업하는 Claude Code에 그대로 붙여 넣는다.

- 운영 앱: `upvible/Rune-PT` (`index.html` 한 파일과 `analyzer.html`, `diag.html`, `journey.html`, `ot.html`, `wlp/`, `avatar/`, `sw.js`, GitHub Pages `https://upvible.github.io/Rune-PT/`). 지금까지 GitHub 웹 업로드로 관리했다.
- 참고 저장소: `chjisceo/rune-pt`의 `feat/path-a-design` 브랜치. `apps/live/`가 운영 앱 원본을 그대로 가져와 기능은 모두 유지하고, Path A 화면을 덧입힌 결과를 만든다. 자세한 내용은 그 저장소의 `apps/live/README.md`에 있다.

목표는 `apps/live`의 빌드 결과를 운영 저장소에 반영하는 것이다. 원본 코드는 거의 그대로이고, 새 파일(`ui/`, `draco/`, `models/`, 아이콘, 매니페스트)이 추가되고, 기존 파일 세 개(`index.html`, `avatar/avatar.html`, `sw.js`)에 짧은 줄이 몇 개 바뀐다.

## 사용자는 개발 초보다

이 작업을 하는 사용자(트레이너)는 터미널, git, npm을 거의 써 보지 않았다. 지금까지 GitHub 웹 업로드로만 배포했다. 사용자가 직접 확인하고 Merge한다. 따로 리뷰해 줄 사람은 없으므로, Claude가 PR을 넘기기 전에 스스로 점검한다.

- 명령은 Claude가 직접 실행한다. 사용자에게 터미널 명령을 입력하라고 하지 않는다. 사용자가 직접 해야 하는 일은 브라우저 로그인 승인(`gh auth login`), GitHub 설정 화면 클릭, PR Merge 버튼뿐이다.
- 필요한 도구(git, gh, Node.js LTS, Google Chrome)가 없으면 무엇을 왜 설치하는지 한 문장으로 말하고, 허락을 받은 뒤 Claude가 설치한다.
- 설명은 쉬운 해요체로 짧게 한다. 전문 용어는 처음 나올 때 한 번 풀어 쓴다. 질문은 예/아니오나 보기 중 고르기로 한다.
- 작업이 끝나면 다음을 남기고 멈춘다.
  - PR 링크와, Claude가 직접 확인한 것(자동 점검 결과, 바뀐 파일 목록)·확인하지 못한 것
  - 사용자가 눌러 볼 주소와 확인할 항목 3~5개
  - 확인이 끝나면 Merge 버튼을 누르는 위치
- GitHub 설정 화면에서 할 일이 있으면, 메뉴 경로를 한 줄씩 적고 사용자가 "했어요"라고 할 때까지 기다린다.
- 사용자가 운영 앱의 다른 수정을 원하면, 웹 업로드 대신 이 저장소에서 별도 브랜치·PR로 처리한다.

## 지켜야 할 것

- 브랜치를 따고 PR을 연다. `main`에 바로 올리지 않는다. GitHub 웹 업로드로 파일을 덮어쓰지 않는다.
- `chjisceo/rune-pt`와 `upvible/Rune-PT`는 커밋 조상이 다르다. `git merge`, `git pull`로 합치지 않는다. 빌드 결과 파일을 복사한다.
- `service_role`·`sb_secret` 키를 어디에도 넣지 않는다. `SB_URL`, `SB_KEY`, `APP_URL` 값을 PR 본문, 커밋 메시지, 로그에 적지 않는다.
- 운영 앱의 계산·저장·로그인 코드를 고치지 않는다. 이번 변경은 화면 덧입힘뿐이다.

## 준비

1. 운영 저장소를 git으로 받는다. 로그인이 안 돼 있으면 사용자에게 `gh auth login`을 안내한다.
2. 운영 저장소 루트에 `AGENTS.md`를 만들고 위 "사용자는 개발 초보다" 절을 그대로 옮긴다. 아래 두 줄을 덧붙인다. `CLAUDE.md`에는 `@AGENTS.md` 한 줄만 둔다. 이 파일은 이 프롬프트가 끝난 뒤에도 매 대화에서 읽히는 상시 규칙이다.
   - `main`에 직접 push하지 않는다. 모든 변경은 브랜치와 PR로 올리고, PR 링크를 사용자에게 준다.
   - `ui/path-a.css`, `ui/path-a.js`, `ui/muscle-viewer.js`는 `chjisceo/rune-pt`의 `apps/live`에서 만들어진 파일이다. 여기서 직접 고치지 말고, 화면 문제는 사용자에게 알린다.
3. 참고 저장소를 운영 저장소 밖에 받고 의존성을 설치한다.
   ```sh
   git clone --branch feat/path-a-design https://github.com/chjisceo/rune-pt.git ../rune-pt-ref
   cd ../rune-pt-ref && npm ci
   ```
4. 3D 근육 모형을 받는다. `.gitignore` 때문에 참고 저장소에 없다. 받은 뒤 SHA-256이 `50c4b67f04929467ed4d839093252dd57dce1ee1db3179ef279ec788f4b6b399`인지 확인한다.
   ```sh
   mkdir -p apps/web/public/models
   curl -L -o apps/web/public/models/stayfit-muscle-skeleton.glb \
     "https://drive.usercontent.google.com/download?id=1n_bGbC0ix8vsnRdm4MbBk_LL6IJGGs_N&export=download"
   shasum -a 256 apps/web/public/models/stayfit-muscle-skeleton.glb
   ```

## 반영

참고 저장소(`../rune-pt-ref`)에서:

```sh
npm run live:sync    # upvible/Rune-PT main 최신을 가져와요
npm run live:smoke   # 빌드하고 Chrome으로 회원·트레이너 흐름을 자동 점검해요
```

- `live:sync`가 가져오는 것은 GitHub에 올라가 있는 운영 저장소 `main`이다. 사용자 컴퓨터에만 있고 아직 안 올린 수정이 있으면 먼저 알려 준다.
- `live:smoke`가 실패하면 사용자에게 고치라고 하지 않는다. 실패 내용을 읽고, 원본이 바뀌어 패치 기준 문장을 못 찾은 경우라면 반영을 멈추고 사용자에게 "Harry님께 이 메시지를 보내 주세요"와 함께 오류 문장을 준다.

통과하면 운영 저장소에서 브랜치를 따고, `../rune-pt-ref/apps/live/dist/`의 내용을 운영 저장소 루트에 그대로 복사한다.

```sh
git switch -c feat/path-a-screens
rsync -a ../rune-pt-ref/apps/live/dist/ ./
git status
```

복사 뒤 확인:

- `git diff`에서 기존 파일 변경은 `index.html`(줄 2개 추가, 1개 변경), `avatar/avatar.html`(2곳), `sw.js`(2곳)뿐이어야 한다. 그 밖의 기존 파일이 바뀌었으면 멈추고 원인을 찾는다. 대개 `live:sync` 이후 운영 저장소가 더 바뀐 경우다.
- 새 파일: `ui/`(화면 스타일·스크립트, 3D 뷰어, 근육 포스터), `draco/`, `models/stayfit-muscle-skeleton.glb`, `icon-192.png`, `icon-512.png`, `apple-touch-icon.png`, `manifest.webmanifest`. 사이트에 없던 앱 설치 파일이라 이번에 함께 들어간다.
- 커밋하고 PR을 연다. PR 본문에 가져온 원본 커밋(`../rune-pt-ref/apps/live/UPSTREAM.json`의 `sha`)과 `live:smoke` 결과를 적는다.

## 사용자 확인

로컬에서 보려면 참고 저장소에서 `npm run live:dev`를 실행하고 `http://localhost:4174`를 연다. 로컬은 서버에 연결되지 않으므로 "로그인 없이 미리보기"로 들어간다. 확인할 항목:

1. 첫 화면이 "오늘 운동"이고, 아래(컴퓨터는 왼쪽) 탭이 오늘·달력·통계·내 정보다. 화면이 `../rune-pt-ref/design-review/proposed/` 시안처럼 검은 바탕에 흰색 주 버튼이다.
2. 운동을 담고 눌러서 세트를 체크하면 숫자가 그대로 쌓인다.
3. "회전해서 보기"를 누르면 근육 모형이 돌고, 쓰는 근육이 색으로 보인다.
4. 내 정보 아래에 아바타가 보인다.
5. 관리자 화면 탭 6개가 그대로다.

Merge한 뒤 실제 주소에서 카카오·구글 로그인, 세트 저장, 선물함, 동기화 표시를 한 번씩 확인한다. 휴대폰은 이전 화면이 캐시에 남아 있을 수 있으니 앱을 완전히 닫았다 연다.

## 이후 운영

- 운영 앱 수정은 지금처럼 운영 저장소에서 한다. `index.html`의 함수 이름(`render`, `viewToday`, `viewMe`, `viewAuth`, `recHTML`, `renderGate` 등)을 바꾸면 새 화면이 해당 부분을 덧입히지 못하고 원본 화면으로 돌아간다. 앱은 계속 동작한다.
- 새 화면이 갱신되면 위 "반영"을 다시 한다. 이미 적용된 패치는 다시 적용되지 않는다.
- React로 완전히 옮기는 작업(`apps/web`)은 별도 계획이다. 이 프롬프트의 범위가 아니다.
